Language

Scripts are a subset of Python, parsed with ruff_python_parser. There is no import system. Host tools are registered by the runtime.

  • assignment, unpacking, and augmented assignment
  • calls, including keyword arguments on print
  • if / elif / else and conditional expressions
  • for over a list, string or dict (a dict yields its keys, as do sorted(d), min(d), enumerate(d) and friends), with break and continue. A loop whose body only reads is pipelined: up to 64 iterations are launched together and each call starts as soon as its own arguments are ready, even when the loop accumulates (total += price(sku), d[k] = v, xs.append(v)). Calls after a break or behind an untaken if are never issued. A loop that writes is pipelined too: its writes stay in order, and each read waits only for earlier writes whose declared footprint overlaps its own (every earlier write if the tools declare no footprints). Names assigned in the loop are usable after it, as in Python; reading one that no iteration assigned is a runtime error.
  • lists, dicts, f-strings, comparisons, boolean operators, and arithmetic (lists compare lexicographically, so sorted and max also work on [key, item] pairs)
  • list, dict and set comprehensions and generator expressions, with nested for and if clauses. They lower to ordinary pipelined loops, so [get(k) for k in keys] issues its calls in parallel. any(...) and all(...) over a generator stop at the first decisive item, as in Python, so their calls run in order. Comprehension variables do not leak.
  • key= on sorted, min, max and xs.sort(), plus reverse= and default=: a one-argument lambda, a tool, a builtin, a helper, str.lower-style methods or a bound method such as counts.get. Sorting is stable and min/max return the first extreme item, as in CPython. map(f, xs) and filter(f, xs) (also filter(None, xs)) give lists.
  • top-level def helpers with positional, keyword and literal-default parameters and return anywhere, including inside loops. Each call is inlined with its locals renamed, so a helper sees the script's globals as they are at the call, and effect analysis, scheduling, replay and limits treat it like the inlined code. Not allowed, each with a fix hint: recursion, nested or indented def, decorators, *args/**kwargs, non-literal defaults, calling a helper before its def, reusing its name as a variable, and changing an argument in place (p.append(x), p[k] = v), because Weave values are not shared between caller and helper.
  • sets: {a, b}, set(xs), set comprehensions and s.add(v). Weave has no set type: a set is a list without duplicates in first-seen order, so len, in, sorted and iteration count match Python but printing a set shows a list.
  • subscripts and common string, list, and dict methods, including str.startswith and str.endswith with a string or list of strings (any match; an empty list is false). Every list element is checked first, so a non-string item is always an error, even if an earlier string would have matched (CPython can return true for the equivalent tuple). For example, url.startswith(["http://", "https://"]). Start/end slice arguments are not supported. Also str.split(sep=None, maxsplit=-1) and str.rsplit
  • builtins str, int, float, bool, abs, round (half to even, as in CPython), len, range, sum, min, max, sorted, reversed, enumerate, zip, any, all, list, dict, tuple (a list), isinstance(x, T) over builtin types (int, float, str, bool, list, dict, tuple, set, or a tuple of them), json.dumps(v) / json.loads(s) without an import, and parse_json(text) (plain JSON text to a value; tool results from MCP servers are text)
  • string formatting as in CPython: f-string format specs ({x:.2f}, {n:,}, {s:>8}, {p:.1%}, {n:05d}, ...), "{} {:.1f}".format(a, b) with positional fields, and printf-style "%s: %.2f" % (name, x). Nested fields in a spec, #, g-type and named fields are rejected with a hint.
  • try / except with one clause: bare except, except Exception, except ToolError, a builtin class (KeyError, IndexError, LookupError, TypeError, ValueError, AttributeError, ZeroDivisionError, ArithmeticError, RuntimeError, AssertionError) or a tuple of them, optionally as e (bound to the error message)
  • raise ValueError("msg") (any class above) and assert cond, "msg". They stop the script like any runtime error; nothing after them runs, and an irreversible call after a raise is never issued.
  • d.update(other) / d.update(k=v), d.pop(k[, default]) and xs.pop([i]) as statements on a plain name, rewritten to rebind the name
  • xs.append(v), xs.extend(ys), xs.sort(...) and xs.reverse() on a plain name, rewritten to xs += [v], xs += ys, xs = sorted(xs, ...) and xs = reversed(xs) (values are immutable, so other receivers such as d["k"].append(v) are an error)

Not supported, each with a one-line error and a fix hint: import, class, while, with, await, yield, global, a bare raise, try/else/finally, and a lambda outside key=/map/filter (assigning one suggests a def).

A bare except and except Exception catch tool failures and ordinary runtime errors. except ToolError catches only tool failures. A builtin class catches runtime errors of that kind: a missing key is a KeyError, an index out of range an IndexError (both LookupError), division by zero a ZeroDivisionError, a missing method an AttributeError, a raised class itself, and every other runtime error both a TypeError and a ValueError (Weave's runtime errors do not distinguish the two). Cancellation and limit breaches are not caught. Indexing a value of the wrong shape (a str or list with a key) names the value it actually got, so the model can repair its script in one step.
