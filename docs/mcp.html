MCP

weave-mcp speaks MCP over stdio. It reads newline-delimited JSON-RPC (the MCP stdio transport) and also accepts Content-Length framing; replies use the request's framing. It always exposes weave_check, weave_run, and weave_replay. --config tools.json also exposes each configured tool, and weave_run uses that config when the request does not pass its own tools list.

cargo run -p weave-mcp -- --config examples/tools.json

An existing MCP client can use examples/mcp-client-config.json. examples/mcp_client.py is a small stdio client that lists tools, calls weather, and runs a script through weave_run.

A configured tool takes args (a list of plain JSON values) and optional kwargs. echo returns the positional argument. const returns the tagged result from the config.

An upstreams list in the config starts other MCP servers, for example {"name": "fs", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/data"], "prefix": "fs_"}. Their tools become callable from scripts under the prefix:

  • Positional arguments fill schema properties in order.
  • The effect comes from effects if listed there, otherwise from readOnlyHint. Tools without either are irreversible.
  • An upstream isError becomes a ToolError.
  • Results are text; read JSON results with parse_json.
