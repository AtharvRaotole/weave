MCP

weave-mcp speaks MCP over stdio. It reads newline-delimited JSON (the MCP stdio transport) or Content-Length framing, and replies in the framing the client used. It always exposes weave_check, weave_run, and weave_replay. --config tools.json also exposes each configured tool, and weave_run uses that config when the request does not pass its own tools list.

cargo run -p weave-mcp -- --config examples/tools.json

An existing MCP client can use examples/mcp-client-config.json. examples/mcp_client.py is a small stdio client that lists tools, calls weather, and runs a script through weave_run.

A configured tool takes args (a list of plain JSON values) and optional kwargs. echo returns the positional argument. const returns the tagged result from the config.

Proxying real MCP servers

An upstreams list in the config starts other MCP servers and lets scripts call their tools. The weave_run description lists them one per line, with parameters in positional order. Parameters that take objects or lists of objects are spelled out, e.g. entities: list[{name: str, entityType: str, observations: list[str]}].

{"upstreams": [
  {"name": "fs", "command": "npx",
   "args": ["-y", "@modelcontextprotocol/server-filesystem", "/data"],
   "prefix": "fs_",
   "results": {"list_directory": "lines"},
   "examples": {"list_directory": {"path": "/data"}}}
]}
  • prefix is prepended to each upstream tool name.
  • effects overrides a tool's effect. Without an override, a tool marked readOnlyHint is read, and anything else is irreversible.
  • results shapes a text result: lines returns a list of non-empty lines, and json returns the parsed value.
  • examples gives sample arguments. Each listed read-only tool is called once at startup, and its truncated output appears in the listing.
